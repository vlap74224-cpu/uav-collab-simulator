# N5：P4 后取消可选 P5、到指定 E 点着陆

原计划保持 P4（必经）→P5（可选）→E（指定降落点）。取消 P5 是资源不足事件的候选处置，确认前不改变实际执行路线，也不提前记作取消。

## 事件与计算

- P4 的实际通过在运动碰撞检查之后记录；默认不再在 P4 强制悬停45秒。
- 场景能耗更新配置在 `mission.resourceLoadUpdate` 中：通过 P4 后，巡航额外消耗每秒0.002个百分点，并至少继续飞行3秒后核查任务余量。该消耗真实进入逐帧电量更新和后续预测；触发事件时不修改电量。
- 单独加载低电量 N5 时，在起飞前依据完整路线及下降耗电设定起始余量；飞行中不重置读数。连续任务保留实际电量，余量充足时继续完成 P5，不制造告警。
- 原计划与缩减计划从同一事件位置、时刻和电量预测。分别保留到达E的余电、包含下降的着陆余电以及对应耗时。
- 完整方案低于15%着陆余量，而缩减方案满足通行及资源要求时，才推荐取消 P5。
- P4 未完成时，先规划并检查 P4→E；若也不足，明确记录保护处置，不强制完成必经任务或自动执行失效候选。
- 决策阶段保留原有全局暂停和真实时间20秒AI接手规则。路线检查完成后才开放接受、呈现预测并启动决策计时。到期执行还要求当前默认候选的通行/资源检查与路线、高度、速度一致。

## 六阶段面板

正常执行、发现不足/正在规划、候选待确认、确认后执行、到E下降、着陆完成，各使用紧凑L1/L2/L3。规划中撤下旧预测；落地前不能显示任务完成。着陆完成后展示实际任务耗时、实际余电和有记录的确认时预测核对，不再显示到达倒计时。

地图将未确认的 P5 显示为“建议取消”，确认执行后才显示“已取消”。完成任务点记录与可选任务取消记录分别保存。
